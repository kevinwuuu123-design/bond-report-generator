# 债券簿记内部报备生成器 2.0

面向债券一级市场簿记完成后的内部报备场景。粘贴簿记同事发送的发行结果后，工具自动识别已有要素、推定常规日期、提示真正缺失的字段，并生成可人工微调的固定报备段落。

## 2.0 重点升级

- 增强对多种真实文本格式的解析：
  - `【简称 发行簿记结果】 + 债券代码`
  - `【简称，代码】`
  - `【简称/代码】`
  - `简称和代码：简称（代码）`
- 支持仅写“7月16日”等无年份日期，并优先从债券简称/“2026年度”推断年份。
- 支持“缴款起息”“债券利率”等常见字段写法。
- `MTN / PPN / SCP / CP / ABN` 自动识别交易商协会品种。
- 交易所简称含 `K` 且为 6 位代码时，可自动识别为“私募公司债（科创债）”。
- 默认利率文案：PPN 用“票面利率”；MTN/公司债用“发行利率”，均可手工覆盖。
- 承销安排改为更灵活的“牵头/角色表述 + 联主 + 销售方式”，可覆盖：
  - 我司牵头且负责存续期管理
  - 我司牵头、簿记管理人
  - 我司牵头受托
  - 其他主承牵头 + 多家联主 + 竞争性销售
- 我司承销规模/份额/承销费整句可直接录入，避免强制套一种格式。
- 归档工作日计数口径可切换：
  - 簿记日次日起算（默认）
  - 簿记日计第1个工作日（用于历史/特殊口径）
- 归档文案可切换：
  - “提交归档 / 归档完毕”
  - “申请报送 / 完成发行底稿报送”
- A类表述前缀、批文状态均支持完整自定义，兼容“批文无剩余额度 / 已使用完毕 / 已发行完毕 / 剩余额度+到期时间”等口径。

## 日期推定规则

- 交易商协会：默认按缴款/起息日前 **1 个工作日**推定簿记日。
- 交易所：默认按缴款/起息日前 **2 个交易日**推定簿记日。
- 起息日：默认等于缴款日。
- 以上均是默认规则，所有日期都允许人工覆盖。跨节假日或项目有特殊安排时，以实际发行安排为准。

## 归档日期与未来年度节假日

- 簿记日后第 **30 个工作日**：拟提交归档/申请报送。
- 簿记日后第 **45 个工作日**：最晚归档/完成发行底稿报送。
- 已内置 2026 年官方法定节假日及调休补班安排，并将 2026 标记为“官方日历已核实”。
- 对 2027 等尚未发布官方节假日安排的年度：
  - 仍按“周一至周五”先给出暂估日期；
  - 页面会明确标黄“暂估”；
  - 官方安排公布后，在“工作日历设置”中补充非工作日、调休补班日，并把对应年度加入“已核实年度”，系统会自动重算。

## 2.0 已针对以下输入形态做逻辑测试

- MTN：带完整债券代码、缴款日
- MTN：标题中“简称，代码”，缴款日不带年份
- PPN：“简称和代码：简称（代码）”，缴款/起息日分列
- 公司债：“简称/代码”，使用“缴款起息”“债券利率”等写法

> 注意：PPN 等协会项目若跨法定节假日，实际簿记安排可能不满足简单的 T-1 工作日关系。系统会自动推定，但必须保留人工覆盖空间。

## 本地运行

```bash
npm install
npm run dev
```

## 部署到 GitHub Pages

1. 在 GitHub 新建仓库，例如 `bond-report-generator`。
2. 上传 / push 本项目全部文件至 `main` 分支。
3. **Settings → Pages → Build and deployment → Source: GitHub Actions**。
4. 项目自带 `.github/workflows/deploy.yml`，push 后自动构建发布。

## 隐私

页面为纯前端工具，项目数据只在当前浏览器内处理；工作日历的人工维护项保存在浏览器 localStorage，不需要后端数据库。
