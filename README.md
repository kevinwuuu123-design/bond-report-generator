# 债券簿记内部报备生成器 v3.0

粘贴簿记结果、核对发行要素、生成内部报备，完成后留存可追溯记录，并导出 Excel 台账。

## 日常使用

1. 粘贴原文，点击“解析要素”，补齐必须项。
2. 点击“完成并归档”，或在必填项齐全后点击“复制并归档”。复制未完成的草稿不会归档。
3. 在“已完成记录”点击债券简称查看完整快照、原始材料和成稿。
4. 使用关键词、市场、簿记日期筛选，导出单笔、已选记录或全部筛选结果的 `.xlsx`。
5. 导出的“发行记录”含全部原始字段及独立数值列，“报备原文”保留成稿及输入原文，“统计说明”披露金额换算和版本口径。

每次归档都是独立快照，已保存的同一表单重复点击不会新增。载入历史记录继续编辑时会另存新记录并保留来源编号；统计同一债券时应核对多个版本，避免重复计数。

## 手机、电脑共用存储

支持 Supabase 邮箱账号登录与云端同步，**需要先完成一次云端开通，详见 [云端开通指南](docs/云端开通指南.md)**。

- GitHub Pages 继续承载网页；项目数据保存到 Supabase 数据库。
- 手机、电脑使用同一项目、同一账号，共享已归档记录。不同账号的记录由数据库 RLS 隔离。
- 在线时每30秒、重新聚焦页面、恢复联网后同步，也可点击“立即同步”。
- 页面已经打开时，网络中断仍可归档到浏览器；恢复连接后重试上传。没有离线安装/离线冷启动功能。
- 本机未登录记录不会自动传入账号，登录后点击“将本机记录导入账号”。
- 不同云端项目、不同账号以及未登录记录的浏览器缓存分别保存，退出账号不会把账号记录显示到未登录台账中。
- 当前共享范围是同一账号，不包含多账号团队空间、权限管理和团队审批。
- 人员建议和工作日历的默认设置仍按设备保存；每条归档记录包含当时的日历快照。

## 备份与隐私

未配置或未登录云端时，输入和记录只保存在当前浏览器，不会上传 GitHub。浏览器清理、无痕模式结束或更换设备可能使本机数据不可用，请定期“备份 JSON”。备份可通过“导入备份”恢复，重复编号会自动去重，编号相同但内容不同则拒绝覆盖。

登录并归档/同步后，记录会上传至所配置的 Supabase 项目。仅使用 `publishable key` 或旧版 `anon` 公钥；禁止把 `service_role`、`sb_secret_`、数据库密码放入网页、GitHub 或前端配置。登录密码由 Supabase Auth 处理，应用不另行保存。

历史记录不提供修改或删除接口；继续编辑时另存快照。如需日后增加删改，请同时设计审计与各设备的同步规则。

## 本地开发

使用 Node.js 24：

```sh
npm ci
npm test
npm run dev
npm run build
```

本地云端连接可以通过界面填写，或复制 `.env.example` 为 `.env.local` 后填写项目地址和公钥。不要提交真实环境文件。

## GitHub Pages 部署

推送 `main` 后 `.github/workflows/deploy.yml` 自动安装锁定依赖、运行测试并构建部署。GitHub 仓库的 **Settings → Pages → Source** 应选择 GitHub Actions。

如果希望两端打开网页就自带同一云端项目，在仓库 **Settings → Secrets and variables → Actions → Variables** 中配置：

- `VITE_SUPABASE_URL`：项目根地址。
- `VITE_SUPABASE_PUBLISHABLE_KEY`：项目公钥。

配置后从 Actions 手动重新运行部署。未配置时仍正常提供本机记录和 Excel 导出。
